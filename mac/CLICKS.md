# 화면 단추 클릭 시험

화면의 누를 것을 하나하나 확인한다. 시나리오 시험(E2E.md)이 모델 함수를 불러 확인하던 탓에
매거진 표지의 '기사 읽기'·'여러 시각'이 눌리지 않는 것(유리 띠 '채우기' 사진이 클릭을 가로챔, 19084ad 에서 고침)을 놓쳤다 —
이 시험은 그런 것을 잡으려고 만든다.

## 돌리는 법

```sh
bugak run --heavy -- mac/scripts/clicksweep.sh [결과 폴더]                 # 기본: 조용한 모드(포커스 없음)
bugak run --heavy -- mac/scripts/clicksweep.sh --real [--idle 3] [결과 폴더] # 실제 클릭(사용자가 쉬는 동안만)
DROPCAP_CLICK_ONLY=onboard,menu,magazine,reader,settings,toast              # 일부 화면만
DROPCAP_CLICK_QUICK=1                                                       # 매거진은 오늘 호 기본 크기·위만(빠른 확인)
```

결과 폴더: `CLICKS-run.md`(항목별 표 + 형 목록) · `results-clicks.json` · `ax-<화면>-<설정>.txt`(화면별 손쉬운 사용 나무) ·
`blocked-activations.txt`(막은 활성화 시도) · `shots/click-fail-*.png`(실패 순간 그림) · `testlog.txt`.
앱은 임시 데이터 폴더·견본 피드(E2EFeeds)로 돌고 실제 기록·네트워크를 쓰지 않는다.

## 두 모드

### 조용한 모드(기본) — 사용자가 이 Mac 을 쓰는 중에도 돌려도 됨
- 앱을 앞으로 띄우지 않는다: `E2EQuietUI` 가 시험 실행에서만 `NSApp.activate…`·`NSRunningApplication.activate`·`setActivationPolicy(.regular)`·`unhide` 를
  막고(기록만), 창을 앞으로 보내는 모든 길(`makeKeyAndOrderFront`·`orderFront`·`orderFrontRegardless`·`order(_:relativeTo:)`)에서 창을
  **투명(alpha 0)·마우스 통과(ignoresMouseEvents)** 로 만든다. 앱이 켜지는 순간(App.init)에 상단바 앱으로 두어 켜질 때도 앞 앱이 되지 않는다.
  창을 화면 밖으로 옮기면 '가려진 창'이 되어 그림이 갱신되지 않아(눌러도 바뀐 것을 못 봄) 자리는 둔다.
- 진짜 커서를 옮기지 않는다. 시스템 메뉴(팝업·Menu 단추·오른쪽 클릭)는 열지 않는다(열면 입력을 붙잡는다) — 이것들은 '맞음만' 확인.
- 시험 앱은 상단바 아이콘·전역 단축키(⌥⌘N·⌥⌘M)를 쓰지 않아 설치된 Dropcap 과 겹치지 않는다. 물방울 소리도 끈다. 시스템 알림은 `swift build` 실행 파일이라 원래 쓰지 않는다.
- 앞 앱 지키기: 시작·화면마다 `NSWorkspace.frontmostApplication` 을 적고, `didActivateApplication` 으로 시험 앱이 앞 앱이 되면 센다(0 이어야 통과).
- 단추마다:
  1. **동작 검사** — 손쉬운 사용 '누름'(같은 프로세스 안 `accessibilityPerformPress`)으로 누르고, 무엇이 일어났는지 본다:
     창 열림/닫힘 · 지면·그림 바뀜(움직임이 멈춘 뒤 비교) · 물방울 · 상태 · 스크랩 · 복사 · 바깥 열기(시험 모드에서는 브라우저 대신 기록) · 초점.
     켬/끔은 값 바꾸기, 옆 목록 줄은 목록 뷰에 직접 누름, 글 칸은 초점 주기.
  2. **맞음 검사** — 같은 자리에 **창 직접 클릭**(`window.sendEvent` 누름·뗌, 앱 활성화·커서 이동 없음)을 보내 SwiftUI 의 실제 클릭 길로
     그 단추가 받는지 본다. 누름은 되는데 직접 클릭이 아무 일도 못 하면 '직접 클릭이 닿지 않음(덮개가 가로챔)' 실패.
     손쉬운 사용 hitTest(가운데 + 안쪽 네 귀퉁이)도 함께 적지만, SwiftUI 는 hitTest 에 실제 클릭 영역(allowsHitTesting·contentShape)을
     반영하지 않아 '상위만 맞음'이 많아 판단에는 쓰지 않는다 — 실제로 아래 되돌림 확인에서 hitTest 는 못 잡고 직접 클릭은 잡았다.
- **시험이 진짜 잡는다는 확인**: 19084ad 의 사진 넘침 고침(RemoteImage·SectionPhotos·SectionCardLab·MenuView·ReaderView)을 되돌린 채 돌리면
  매거진 오늘 호 '여러 시각 4곳'이 **누름은 됨 · 직접 클릭: 아무 일 없음 → 실패**, 고침을 되살리면 통과(결과 폴더 revert3 / fixed1).

### 실제 클릭 모드(--real) — 사용자가 쉬는 동안만
- 진짜 마우스 이벤트를 이벤트 대기열에 넣는다(앱 활성화). 누르기 전마다 `CGEventSource.secondsSinceLastEventType(.combinedSessionState)` 로
  마지막 사용자 입력이 `--idle` 분(기본 3) 넘었는지 보고, 아니면 앱을 숨기고 다시 한가해질 때까지 기다린다(시험 앱이 보내는 이벤트는 시스템 입력 시각을 바꾸지 않음).
- 진짜 커서 이동은 이 모드에서도 기본 끔(`DROPCAP_TEST_WARP=1` 일 때만). 오른쪽 클릭 메뉴는 이 모드에서만 연다.

## 무엇을 잡고 무엇을 못 잡나

| 잡음 | 못 잡음 |
|---|---|
| 다른 뷰가 클릭을 가로챔(넘친 사진·overlay·offset·scaleEffect) — 직접 클릭이 닿지 않음 | 시스템 메뉴 안의 항목(조용한 모드는 메뉴를 열지 않음) |
| 눌러도 아무 일 없는 단추(동작 연결 빠짐) | 마우스 올림(hover)으로만 나타나는 단추(커서를 옮기지 않으므로) |
| 눌렀더니 엉뚱한 일(창·지면·상태 변화를 적어 둠 — 기대와 맞는지는 표를 보고 판단) | 끌기·두 번 누름·키보드 단축키(읽기 창 J·K·Esc 는 창에 직접 보내 확인) |
| 고르기 상태의 단추(이미 고른 칩·줄)는 '이미 고른 것'으로 구분 | 사용자 화면에서의 실제 모양(창이 투명) — 모양은 시나리오 시험 스냅샷으로 |
| 시험 앱이 앞 앱이 되는 것(포커스 뺏기) | 손쉬운 사용 나무에 나오지 않는 누를 것(아래 '알려진 한계') |

알려진 한계
- SwiftUI 손쉬운 사용 나무는 시험 실행에서 `AXEnhancedUserInterface` 를 켜야 만들어진다(App.init 에서 켬). 게으른 묶음(카드 격자)은 화면에 보일 때만 아이들이 생겨 스크롤 '아래' 설정에서 따로 본다.
- 옆 목록(NSOutlineView)은 나무에 줄이 안 나와 줄 사각형으로 더한다.
- 직접 클릭의 '일어난 일'이 초점 변화뿐인 경우도 닿은 것으로 본다(덮개가 가로채면 초점도 안 바뀐다).

## 공통 컴포넌트: 형마다 대표만

같은 동작의 공통 컴포넌트(분야 유리 카드·표지 카드·목록 줄·칩·옆 목록 줄 등)는 지면마다 되풀이해 시험하지 않는다.
**형 열쇠 = 역할 · 높이(10px 단위) · 폭(좁음 ≤120 · 보통 · 넓음 >400) · 사진 있음 여부**. 한 지면에서 두 번 이상 나오거나 앞 지면에서 이미 본 형이면 공통으로 보고
앱 전체에서 **처음 만난 것 1개만** 맞음·동작 검사, 나머지는 결과 표에 `같은 형(대표: …)`로만 남긴다. 사진 있음/없음·크기가 다르면 다른 형이라 변형마다 1개씩 검사된다.
한 지면에서 한 번만 나오는 단추는 지면 고유(그 지면만의 단추·연결)로 보고 이름까지 열쇠에 넣어 각각 검사한다.
형 목록과 대표·나온 수는 `CLICKS-run.md` 끝 '형 목록'에 자동으로 적힌다.

### 시험이 잡는다는 확인(되돌림)
19084ad 의 사진 넘침 고침을 되돌리고(RemoteImage·SectionPhotos·SectionCardLab·MenuView·ReaderView) 조용한 모드로 매거진 오늘 호를 돌리면
`'여러 시각 4곳' — 누름은 됨 · 직접 클릭: 아무 일 없음 → 실패(직접 클릭이 닿지 않음)`. 고침을 되살리면 통과. 손쉬운 사용 hitTest 는 두 경우 모두 '상위만 맞음'이라 구별하지 못했다(그래서 직접 클릭을 맞음 검사로 씀).

### 고친 것(앱)
- **스크랩북 메모 칸이 글자 위만 눌림** — 메모 줄의 빈 곳을 눌러도 쓰기가 시작되지 않았다(세로 TextField + Spacer). 칸이 줄을 채우고 누르면 초점(`MagazineView` ScrapRow 3줄).
- 시험 모드 전용: 시험 앱은 상단바 아이콘·전역 단축키를 쓰지 않음(`App.swift` MenuBarExtra isInserted · `HotKey.register`), 브라우저를 열지 않고 기록(`ExternalLink.open`), 앱 활성화·창 보이기 막음(`E2EQuietUI`, App.init 한 줄).

### 클릭 시험을 만들며 찾은 것(시험 쪽 — 앱 문제 아님, 기록만)
- 손쉬운 사용 값이 NSNumber 로 오면 String 으로 바로 받다 예외 → Swift 작업 안에서 삼켜져 main 큐가 멈춘 것처럼 보였다(앱 정지로 오인). 값을 객체로 받아 확인하도록 고침.
- 시험 앱이 `NSWindow(contentRect:)` 로 만든 창을 닫으면 기본값(isReleasedWhenClosed)으로 두 번 풀려 죽었다 → 시험 창은 끄고 씀.
- 열기·닫기 움직임 중에 창을 투명하게 바꾸면 AppKit 이 죽었다 → 시험 창은 움직임 없음(`animationBehavior = .none`).
- 실제 클릭 첫 순회에서 '사회' 카드·옆 목록 줄이 '아무 일 없음'으로 나온 것은 앞 클릭의 움직임이 끝나기 전에 그림을 비교한 탓(움직임이 멈출 때까지 기다리게 고친 뒤 통과).

### 남은 것·못 본 것
- 시스템 메뉴 안 항목(잠시 끄기 시간·정렬 종류·더 보기 메뉴·오른쪽 클릭 '바로 줄이기')은 조용한 모드에서 열지 않는다 → `--real` 로 쉬는 동안 확인할 것. 이번 작업 중에는 사용자가 Mac 을 쓰고 있어 `--real` 은 돌리지 않았다.
- 물방울 카드(누름·닫기·칩)는 실제 클릭 모드에서만.
- 사진 있음/없음 변형: SwiftUI 가 카드 단추 안 사진을 손쉬운 사용 나무에 따로 내놓지 않아 '사진' 여부는 구별되지 않았다 — 카드는 크기(높이)로 형이 나뉜다.
- 직접 클릭의 '일어난 일'이 초점 변화뿐이어도 닿은 것으로 본다(덮개가 가로채면 초점도 안 바뀐다 — 되돌림 확인에서 확인).
