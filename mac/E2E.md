# 사용자 흐름 시나리오 시험(끝에서 끝까지)

> 상태: 반영됨(2026-10-14, 시나리오 1~22단계).

사람이 쓰는 순서(첫 실행 → 분야 고르기 → 알림 → 묶음 → 줄이기 → 다시 시작·복구)를 앱을 띄워 자동으로 밟고,
단계마다 기대값을 검사(통과/실패)하고 스냅샷·로그를 남긴다. 실제 기록·네트워크는 쓰지 않는다.

## 돌리는 법

```sh
bugak run --heavy -- mac/scripts/e2e/run.sh [결과 폴더]      # 기본: mac/.build/e2e/<시각>
```

- 빌드(`swift build`) → 앱을 세 번 띄움: `main`(1~11단계) → `restart`(12-가) → 상태 파일·DB 를 깨뜨림 → `recover`(12-나·다).
- 결과 폴더: `E2E-run.md`(단계 표) · `results-*.json` · `e2e.log`(시험 시계 시각 포함) · `shots/*.png` · `app-*.log` · `export.opml`/`import.opml` · `facts-*.json`.
- 한 번 도는 데 약 6분(묶음 단계는 앱의 1분 점검을 실제로 기다린다).
- **사용자 화면을 건드리지 않는다**(2026-10-14~): 시험 실행은 앱을 앞으로 띄우지 않고 창을 투명·마우스 통과로 둔다(`E2EQuietUI` — CLICKS.md '조용한 모드'). 상단바 아이콘·전역 단축키·물방울 소리도 끈다. 예전처럼 보이게 돌리려면 `DROPCAP_TEST_REAL_UI=1`.
- 논리 부분은 `swift test` 에도 들어 있다: `Tests/DropcapTests/E2EScenarioTests.swift`(견본 이야기가 설계대로 묶이는지, 4·5·11단계 정책 순서, 묶음 시각·방해 금지, 견본 피드 해석, OPML 왕복, 시험 모드가 아닐 때 아무것도 안 바뀌는지).

## 찾은 버그와 처리(e2e-fix)

1. **스크랩이 매거진 DB 와 함께 사라짐 — 고침.** DB 를 새로 만들 때 치운 `.broken.sqlite` 의 `scraps` 표를 읽기 전용으로 열어 읽히는 줄까지 옮기고(`Database.salvageScraps`), 스크랩이 바뀔 때마다 전체를 `scraps.json`(데이터 폴더, 원자적 쓰기)에 사본으로 둔다. DB 를 새로 만들었거나(깨짐) 기사도 없는 빈 DB 인데 사본이 있으면 DB 에 없는 스크랩을 사본에서 되살린다(평소에 다 지운 것은 되살리지 않음). 예전 판(사본 없음)은 첫 실행에 사본을 만든다. 예전 판으로 되돌려도 사본은 무시될 뿐이고, 끄기는 `defaults write … scrapsCopyOff -bool true`. 데이터 폴더째 옮기면 사본도 따라간다.
   시험: `E2EFixTests.scrapCopyRoundTripAndRestoreList`·`salvageScrapsFromOtherFile`·`corruptDBIsMarkedRecreated`, 시나리오 12-다(완전히 깨진 파일 → 사본에서 2개).
2. **번역 실패인데 'Google 번역' 표시 — 고침.** `ArticleService` 가 실제로 바뀐 문단 수를 세어, 0이면 `translated = false`·표시 없음, 일부만이면 '… · 일부 번역'(`ArticleService.engineLabel`). 번역 안 된 문단은 원문 보기 대상에서 뺀다. `Translator` 는 손대지 않음(작업자 E 담당). 시험: `E2EFixTests.translationLabel`, 시나리오 9-마.
3. **'이 분야 덜 받기' 뒤에도 주요 뉴스 흐름으로 떨어짐 — 결정대로 고침.** `SectionPolicy.less`(예전 파일엔 없음 → false). 덜 받기를 누르면 켜지고, `NotifyPolicy.decideWithTop` 이 이 분야는 주요 뉴스 흐름으로 보지 않는다(국내 8곳 큰 소식도 묶음으로). 설정 › 분야에서 즉시로 되돌리면 풀린다. 누를 때 안내 "이 분야는 저녁 묶음으로 모아 드릴게요"(매거진만이 되면 "매거진에만 실을게요") — 안내는 `AppModel.lessOf` 에서 띄워 관리자 소유 `SectionViews` 는 건드리지 않음. 시험: `lessOfStaysOutOfTopFlow`(예전 `lessOfStillReachesTopFlow` 를 바꿈)·`lessFlagSurvivesOldAndNewFiles`, 시나리오 11-나.
4. **분야 칩이 출처 분야만 따름 — 고침.** `Sections.place` 가 분야별 걸린 낱말 수를 세어(`Sections.hits`), 대표(출처) 분야와 다른 분야가 2개 이상이고 대표 분야보다 많으면 '강한' 분야로 칩에 더하고 `NewsItem.extraTopic` 으로 목록 줄·첫 소식 카드에 칩을 하나 더 보인다. 알림 분야는 `AppModel.notifySection` 이 칩 가운데 고른 분야를 먼저 쓴다(정적 함수로 빼 시험). 시험: `E2EFixTests.strongKeywordChip`, 시나리오 9-라.
5. **물방울 카드 분야 칩이 '…' 로 잘림 — 고침.** 원인: 머리 줄 `HStack`(출처명·칩·외 N곳·Spacer·시각)이 오른쪽 사진 때문에 좁아질 때, 칩(`TopicChip`)에 고정 크기가 없어 SwiftUI 가 칩을 먼저 줄였다(출처명 `lineLimit(1)` 과 같은 우선순위). 칩과 '외 N곳'에 `.fixedSize()` 를 주어 출처명이 먼저 줄게 했다.
   확인 방법: 시나리오의 물방울 스냅샷(`shots/main-04-drops.png`)을 본다 — 화면 밖 그리기라 바탕은 흐리지만 배치(layout)는 실제와 같다. 고치기 전 `run2` 는 칩이 아이콘+'…', 고친 뒤 `run3` 는 '국제'·'경제' 가 다 보인다.

윈도우·리눅스 판에는 이 다섯 가지를 아직 옮기지 않았다(FEATURES 의 해당 줄에 '맥만 반영(e2e-fix)' 표시).

### 찾아서 고친 것

1. **첫 실행에 앱 전체 비동기가 멈춤 — 심각, 고침.** 분야 사진 점수(`PhotoQuality.textRatio`, Vision 글자 읽기 — 동기 호출)를 분야 12개가 `Task.detached` 로 동시에 돌려, Swift 동시성 공용 스레드 10개가 모두 Vision 안에서 막혔다(sample 로 확인). 그 뒤로는 확인·알림·`Task.sleep` 이 모두 멈춰 앱이 아무것도 하지 않았다(run4·run5 에서 1단계부터 15분 정지). 고침: `PhotoQuality.scoreAsync` — 전용 직렬 DispatchQueue 에서 차례로(호출부 `SectionPhoto.pick`·`Magazine` 사진 채우기·`ExtrasTestHooks` 교체). 시험: `E2ESettingsTests.photoScoringDoesNotStarveConcurrency`(24장을 한꺼번에 재는 동안에도 짧은 잠이 제때 깨어남), 시나리오 1단계(5초 안에 통과).
2. **출처를 꺼도 위젯에 남음 — 고침.** 위젯 내보내기 방아쇠가 `recent.first` key·안 읽음·마지막 확인만 봐서, 끈 출처 글이 이미 읽은 것이면 위젯을 다시 쓰지 않았다. 고침: 방아쇠가 SourceFilter 를 거친 앞쪽 목록 key 를 본다(`Integrations.start`). 13단계.
3. **출처를 꺼도 안 읽음 수가 그대로, 다시 켜도 안 돌아옴 — 고침.** 안 읽음은 '새로 온 수' 계수기라 `min` 으로 줄이기만 했다. 고침: 안 읽음에 든 소식 key(`AppState.unreadKeys`, 예전 파일엔 없음 → 예전처럼 줄이기만)를 기억해 보이는 것만 센다(`AppModel.recountUnread`). 직접 추가 채널을 다시 구독할 때도 다시 센다. 시험 `unreadFollowsVisibility`·`oldStateWithoutUnreadKeys`, 13·14·15단계.
4. **출처 숨기기·낱말 알리지 않기가 목록에서 글을 지움 — 고침.** `hideSource` 는 `recent` 에서 지우고, `reapplyKeywords` 는 알리지 않음 낱말이 든 글을 지워, 숨김 해제·낱말 삭제 뒤에도 돌아오지 않았다(SourceFilter 의 '지우지 않고 거르기'와 어긋남). 고침: 둘 다 거르기만(`visibleRecent` 가 숨김·꺼짐·알리지 않음 낱말을 거름), 숨기기/해제는 `subscriptionsChanged`(대기열·안 읽음·화면 갱신). 새로 받는 글 중 알리지 않음 낱말이 든 것은 예전처럼 받지 않는다. 시험 `hideAndMuteAreFiltersNotDeletes`, 17·20단계.
5. **설정 창 '거르기' 칸이 옛 글자로 되돌림 — 고침.** 칸은 창을 처음 열 때만 채워지고 탭을 옮기거나 닫을 때 저장해, 그사이 바깥(카드의 '이 낱말 알리지 않기' 등)에서 바뀐 낱말을 옛 글자로 덮었다(run9 22단계: 지운 '지역화폐'가 다시 알리지 않음에 들어가 경제 알림이 모두 막힘). 고침: 낱말이 바뀌면 칸도 따라감(`SettingsView` `onChange` 두 줄, `splitKeywords`). 20단계 끝 확인.

### 확인만 한 것

- run6 에서 13단계 직후 앱이 충돌 보고 없이 끝난 적이 한 번 있었다. 이후 실행(종료 코드를 남기도록 바꾼 run7~)에서는 다시 나오지 않아 원인을 찾지 못했다.
- 21단계의 글꼴 토글은 SwiftUI 스위치(PlatformSwitch)라 AppKit 제목·손쉬운 사용 이름이 비어 있어 시험이 찾지 못했다. 그래서 토글이 하는 일(설정값 저장 + `Appearance.changed()`)을 직접 하고 결과를 봤다 — 토글 자체를 누르는 것은 눈으로 확인할 것.
- 다시 켠 출처의 대기열(묶음으로 고였던 것)은 돌아오지 않는다(끌 때 대기열에서 빼므로). 목록·매거진에는 돌아온다.

## 자동으로 확인하지 못한 것

- **눈으로 볼 것**: 유리 카드·물방울·매거진·읽기 창의 모양(스냅샷만 남김). 물방울 패널은 화면 밖 그리기라 반투명 바탕이 비어 글이 흐리게 찍힌다(실제 화면과 다름). 상단바 목록은 `ImageRenderer` 로 그려 검색창·메뉴 같은 시스템 컨트롤이 노란 자리표시로 나온다. 확인 창 글은 창 안 글자를 읽어 확인했고 그림에는 단추만 찍힌다.
- **묶음 '제목 2줄'**: 이 시나리오의 묶음은 1~2건이라 2줄 모양은 `DROPCAP_TEST_BUNDLE` 견본으로 따로 볼 것.
- **해외/국내 나란히(매거진 스토리)**: 오프라인에서는 한국어 제목을 영어로 바꾸지 못해(Google 막힘) 국내·해외 기사가 한 스토리로 묶이지 않는다. 두 지역이 섞인 스토리는 실제 네트워크에서만 생긴다.
- **번역**: 시험은 바깥 요청을 막으므로 번역 결과는 보지 못함(번역 실패 때의 표시만 확인 — 9-마).
- **실제 피드·네트워크·안전 검사 자체**, 시스템 알림(알림 센터) 방식, 클릭·키보드 조작(이 Mac 은 손쉬운 사용 권한이 없어 내부 API 로 대신 부름 — 분야 카드를 누르는 대신 `chooseSections`, 확인 창은 '저장' 을 코드로 누름), 잠들기·깨기, 아침 브리핑(시나리오에서 끔).
- **실제 시각**: 하루 흐름은 시험 시계로 옮긴 것이다. 앱의 1분 점검 타이머는 실제 시간으로 돈다.
- 실행 중 `UserDefaults`(목록 정렬·모양)를 잠깐 바꾸고 되돌린다. `swift build` 실행 파일은 설치된 앱과 다른 설정 영역을 쓴다.
