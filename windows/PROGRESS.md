## 프록시 경유 DNS 바꿔치기(보안 점검 W6, 2026-10-15)

- 문제: 시스템 프록시를 쓰면 목적지 이름은 프록시가 풀어 접속 IP 를 볼 수 없었고, 막는 것은 요청 전 검사(`UrlSafety.ResolvesPublicAsync`, 5분 기억)뿐이었다 — 그 사이 이름이 내부망을 가리키게 바뀌면 프록시를 거쳐 내부망으로 요청이 나갈 수 있었다.
- 고침: `SafeHttp` 클라이언트 앞에 `ProxyGuard`. 프록시를 쓰는 요청(프록시 예외 목록에 든 주소는 직접 연결 — 그쪽은 예전처럼 접속 IP 검사)은 **보내기 직전에 목적지 이름을 기억 없이 다시 풀어** 모든 주소가 공개 대역일 때만 보낸다(리다이렉트 매 단계, WebView2 대리 받기도 같은 길). 풀리지 않는 이름도 막음(직접 연결과 같음).
- 하지 않은 것(결정대로): 프록시 응답을 출처 피드 도메인으로 제한하지 않음 — 맥에서 해 보니 사진 CDN·출처 밖 기사·번역이 프록시 사용자에게 막혀 되돌렸음.
- **받아들인 위험**: 이 확인과 프록시가 이름을 다시 푸는 순간 사이에 이름이 바뀌면(아주 짧은 TTL 의 바꿔치기) 막을 수 없다. 프록시 자체를 통해 IP 로 접속을 고정할 방법이 HTTP 프록시에는 없다. 프록시를 쓰는 사용자는 회사망 등 관리되는 망이 대부분이라 낮음으로 둔다.
- 시험: `ProxyDnsTests`(가짜 로컬 프록시 + 바꿔 끼운 DNS) — 내부망·루프백·풀리지 않는 이름으로 바뀐 목적지는 프록시로 나가지도 않음, 공개 주소(출처 밖 CDN 포함)는 그대로 프록시로, 같은 이름이 공개 → 내부망으로 바뀌면 두 번째 요청은 막힘. 고치기 전 3개 중 2개 실패 → 고친 뒤 통과.
